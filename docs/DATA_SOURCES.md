# 실데이터 연결 가이드

Trade Checker 리포트는 6개 영역을 확인합니다. 영역마다 데이터를 주는 곳이 다르고, 한 업체가 모든 영역을 주지는 않습니다.
그래서 `DATA_PROVIDER=live` 공급자는 여러 출처를 **동시에** 조회해 하나의 리포트로 합칩니다.

| 영역 | 연결된 출처 | 비용 | 상태 |
|---|---|---|---|
| 기업 식별 (법인 실재·설립일·활성 여부) | GLEIF 법인 등록부 | 무료 · 키 없음 | ✅ 바로 동작 |
| 웹사이트·이메일 (도메인 개설 시기, 무료 메일 여부) | RDAP 도메인 등록 정보 | 무료 · 키 없음 | ✅ 바로 동작 |
| 제재·수출통제·사기 명단 | OpenSanctions | 상업용 유료 | ✅ 키만 넣으면 동작 |
| 신용점수 · 소송 · 파산 | Creditsafe Connect | 유료 계약 | 🟡 연결 완료, 계약 후 필드 확인 필요 |
| 통관(B/L) 실적 | ImportGenius · Panjiva · Volza 등 | 유료 계약 | 🟡 연결 틀만 있음 (계약 시 필드 목록 제공) |

## 1. 지금 바로 켜는 방법 (무료)

Vercel 환경변수에 `DATA_PROVIDER=live` 하나만 넣고 다시 배포하세요.

- 법인 등록부와 도메인 정보로 **실제 회사**를 조회합니다.
- 연결되지 않은 영역은 리포트에 '미연결'로 표시됩니다. 확인하지 못한 영역을 '문제없음'으로 보지 않습니다.
- **데이터 충실도**(확인한 영역 수)에 따라 최고 등급을 제한합니다.
  - 5개 이상이면 A까지
  - 3~4개이면 최고 B
  - 2개 이하이면 최고 C (선결제·신용장 권장)
- 무료 출처만 쓰면 대부분 **C등급 이하**로 나옵니다. 의도된 동작입니다.

> **한계를 미리 알아 두세요.** LEI(법인식별기호)는 금융거래·대기업 위주로 발급되어 **중소 바이어는 없는 경우가 많습니다.**
> 이때는 '등기 없이 조회' 후보로 진행되며, 제재 명단과 도메인만 확인합니다.

## 2. 단계별 도입 순서 (권장)

### 1단계 · 출시 직후: 무료 + 제재 명단 (월 고정비 거의 없음)

**OpenSanctions** 상업용 라이선스를 사서 `OPENSANCTIONS_API_KEY` 를 넣습니다.

- 미국 OFAC, EU, UN 제재 목록과 수출통제 명단, 인터폴 수배, 사기 관련 명단을 한 번에 검색합니다.
- 제재 대상과 일치하면 **F등급으로 고정**하고, 근거 링크를 보여 줍니다.
- 비용은 조회 1건당 1크레딧 선불 방식입니다. 비상업 용도는 무료입니다.
- 같은 회사는 24시간 동안 캐시해 중복 과금을 막습니다.

### 2단계 · 유료 고객이 생기면: 신용평가 (핵심)

**Creditsafe** 와 API 계약을 맺습니다. 무료 API 체험을 신청할 수 있고, 200여 개국을 다룹니다.

1. 샌드박스 계정을 받으면 다음을 실행해 실제 응답 형식을 내려받습니다.
   ```bash
   CREDITSAFE_USERNAME=… CREDITSAFE_PASSWORD=… node tools/creditsafe-schema.mjs AE "회사명"
   ```
2. `lib/sources/creditsafe.js` 의 `FIELD_PATHS` 를 실제 필드 이름에 맞게 고칩니다.
   - 공개 문서에는 엔드포인트만 있고 리포트 안의 필드 위치가 나와 있지 않아, 지금은 '후보 경로'입니다.
   - 경로가 틀려도 오류는 나지 않습니다. '정보 없음'으로 표시됩니다.
3. `node tests/live-sources.test.mjs` 의 Creditsafe 가짜 응답도 실제 형식으로 바꿔 테스트합니다.
4. 리포트 1건이 과금 단위이므로 30일간 캐시합니다. 기간은 `lib/server/cache.js` 의 `TTL_HOURS` 에서 바꿉니다.

**대안**

- **Dun & Bradstreet** (D&B Direct+): 비싸지만 신흥국 커버리지가 강하고, DUNS 번호로 식별합니다.
- **한국무역보험공사(K-SURE) 해외기업 신용조사**: 공개 API는 확인되지 않았습니다. 리포트에서 고객에게 직접 신청하도록 안내합니다. 중소기업은 무료 이용 혜택이 있습니다.
- **KOTRA 해외 바이어 신용조사**: 유료 대행 서비스입니다.

### 3단계 · 차별화: 통관 실적

'실제로 물건을 수입하는 회사인가'는 페이퍼컴퍼니와 무역 사기를 가려내는 가장 강한 신호입니다.

- **ImportGenius API**: Enterprise 요금제 또는 API 추가 계약이 필요하며, 25개국 이상을 다룹니다. 접근 토큰과 필드 목록은 계약 때 받습니다.
- 대안은 S&P Global Panjiva, Volza, 한국무역협회 데이터입니다.
- 계약하면 `lib/sources/importgenius.js` 의 `shipments()` 를 채웁니다. 선적 목록을 월별 건수로 바꾸는 `toCustoms()` 도우미는 이미 있습니다.

## 3. 계약 전에 꼭 확인할 것

1. **재판매(재배포) 권한**
   - 데이터 업체 리포트를 내 서비스 고객에게 보여 주려면 '플랫폼·재판매' 라이선스가 필요한 경우가 많습니다.
   - 사내용 라이선스로는 고객에게 보여 줄 수 없습니다. 계약서에 "제3자(고객)에게 결과 표시 가능" 문구가 있는지 확인하세요.
2. **신용정보법 해당 여부**
   - 기업의 신용을 평가해 다른 사람에게 제공하는 일은 국내법상 신용정보업 허가 대상이 될 수 있습니다.
   - 서비스 형태(평가 등급 제공 vs 공개정보 정리·위험 신호 안내)에 따라 달라지므로, **출시 전에 변호사 검토**를 받으세요.
   - 그 전까지는 '신용등급'이 아니라 **'무역 안전 등급(참고 지표)'** 이라는 표현과 면책 문구를 유지하세요. 이미 그렇게 되어 있습니다.
3. **제재 명단 일치 = 동명이인 가능성**
   - 이름이 비슷한 다른 회사일 수 있습니다. 리포트에는 근거 링크와 '등록번호·주소 대조' 안내가 함께 나갑니다.
   - 일치도 기준은 `OPENSANCTIONS_THRESHOLD`(기본 0.75)로 조정합니다.
4. **데이터 기준일 표시**: 리포트의 데이터 출처 항목마다 '○○ 기준' 날짜가 표시됩니다(캐시 시점).

## 4. 비용 구조 감각 잡기

- 무료 출처: 0원
- 제재 명단: 조회당 과금 (캐시로 같은 회사 반복 과금 방지)
- 신용 리포트: 건당 또는 연간 묶음 계약. 보통 가장 큰 비용입니다.
  - Trade Checker 요금제(Starter 월 20건, Team 월 150건)를 정할 때는 **건당 원가**를 먼저 받아 마진을 계산하세요.
- 통관 데이터: 연간 구독형이 많습니다.
- 견적은 업체마다, 국가 범위마다 크게 다르므로 2~3곳 견적을 비교하세요.

## 5. 비용·안정성 보호 장치 (이미 들어 있음)

- 유료 출처(제재 명단·신용평가·통관)는 **조회 건수를 먼저 차감한 뒤에만** 부릅니다. 실패하면 차감을 되돌립니다.
- 로그인 없는 데모(Supabase 미연결)에서는 유료 출처를 부르지 않습니다.
- 링크로 열린 검색은 후보만 보여 주고, 사용자가 회사를 고를 때만 차감합니다.
- 한 사람당 1분에 12건까지만 조회할 수 있습니다(`SEARCH_RATE_PER_MIN`).
- 같은 회사의 동시 조회는 한 번만 부르고, 결과는 출처별 기간 동안 캐시합니다.
  - 캐시 키는 회사 이름·국가·등록번호·도메인을 합쳐 만듭니다. 이름이 비슷한 다른 회사와 섞이지 않습니다.
- 조회 한 건 전체에 시간 제한(`LIVE_DEADLINE_MS`, 기본 20초)을 둡니다.
  - 시간 초과는 재시도하지 않고, 과금되는 호출도 자동 재시도하지 않습니다.
- 관심 거래처 '다시 확인'은 1시간 안에 반복하면 외부 API를 다시 부르지 않습니다.
- 출처마다 다른 회사를 같은 회사로 맞출 때는 등록번호가 같거나, 법인 형태까지 포함한 이름이 같아야 합니다.
- `.com`·`.net` 같은 일반 도메인이 등록되어 있지 않으면 위험 신호(+20)를 줍니다.
  - 국가 도메인(.ae 등)은 등록 정보를 공개하지 않는 곳이 많습니다. 그래서 정보가 없어도 위험 신호를 주지 않고 '확인 불가'로만 표시합니다.

## 6. 구조 (개발자용)

```
lib/sources/            출처별 연결부 (각자 독립, 실패해도 다른 출처는 계속)
  http.js               시간 제한·재시도·오류 구분
  gleif.js  rdap.js  opensanctions.js  creditsafe.js  importgenius.js
lib/providers/live.js   여러 출처를 동시에 조회 → Profile 하나로 합치기
lib/server/cache.js     출처별 캐시 (Supabase source_cache 테이블)
lib/engine.js           제재·도메인 나이·법인 상태·데이터 충실도 신호 추가
supabase/migrations/0002_live_data.sql   캐시 테이블 (서버만 접근)
tests/mock-data-sources.mjs              실제 API와 같은 형식의 가짜 서버
tests/live-sources.test.mjs              20개 시나리오
tests/live_ui_test.py                    실데이터 모드 화면 점검 (PC·모바일)
```

새 출처를 추가할 때는 다음 순서로 합니다.

1. `lib/sources/새출처.js` 에 조회 함수를 만듭니다.
2. `live.js` 의 `Promise.allSettled` 목록에 넣습니다.
3. 결과를 Profile 필드로 옮기고 `coverage` 를 표시합니다.
